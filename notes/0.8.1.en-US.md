# Pure Tokens Switch 0.8.1

Corrects client version discovery and configuration compatibility, aligns models, usage, account and wallet records with Web, and improves canvas failure messages. 

The group hint now explains that image and video models require selecting the corresponding provider groups and installing the skill before use. The hint uses a light amber background and dark brown text, with an absolute pseudo-element offset separating it from the selector without adding layout space. A keyboard-accessible close button dismisses both the tip and the animated orange-gold selector highlight, restoring the normal border. The choice is saved in local preferences across client switches, page visits and app restarts. Both the tip and close button float outside document flow; the group row stays 56px tall with no extra padding or margin. Accessible group guidance remains available.

## Redemption failure reasons

- Expired codes and invitation eligibility failures show their specific reason instead of a generic top-up failure. Pending requests retain the original retry action, review-required claims remain protected against duplicate submission, and unknown errors hide internal diagnostics.

## Video tutorial shortcut

Added a Video tutorial button beside Usage examples in configuration confirmation, opening the Bilibili tutorial profile in the system browser.

## Notification settings

- Removed the test-notification control from Settings while retaining notification preferences and necessary permission guidance. System-managed permissions no longer show permission-denied guidance.

## Client version discovery

- Sixteen supported CLIs prefer their own fixed version command: Grok uses version; the others use --version. Fallback metadata must belong to the same installation. Unverifiable versions remain unknown.
- Hermes displays its desktop shell and local Agent versions separately. Blank and 0.0.0 placeholders are hidden without changing installation status or configuration availability. Remote backend versions and other installations are not substituted. Embedded Codex CLI detection uses its own version instead of the desktop version.
- Queries have time and output limits, closed stdin, timeout process cleanup and cached results. Verified Windows npm entrypoints run directly through Node without a shell. Third-party version commands may still perform their own update checks.
- GUI clients continue to use metadata from their corresponding installation. Configuration-write, restart and credential permissions are unchanged.

## Canvas operations

- Creation failures identify invalid names, limits or account problems while retaining the current canvas and input. Failed creation is not automatically retried.
- Deletion failures identify conflicts, the last canvas and unsettled tasks. Unknown failures do not expose internal storage details.
- Internal separation of creation, deletion, history and media editing preserves drafts, switching, saving and transaction rollback behavior.

## Client configuration and detection

- Claude Desktop consistently labels credentials as “API Key”. Mapped connections use “Set up & enable local routing” on the primary button, without a separate mapping-status line above the models. Direct setup, security confirmation and failure feedback are unchanged.

- Claude-3p accepts its default bearer authentication and preserves ordinary host preferences. Windows Claude Desktop uses Local AppData instead of the old Roaming directory. Reapply configuration after upgrading; old files remain intact, and host activation and model calls still require real-device checks.
- Ordinary provider and model settings survive reconfiguration across supported clients. Conflicting endpoints, authentication or protocols, and operations that would discard preferences still preserve the original file. Preference conflicts are not reported as corruption.
- Detection timeouts offer a retry instead of reporting an absent installation. Refreshing one client no longer drops other clients from the initial scan. Stopping the wait does not prove a blocked background probe has terminated.

## Models, usage and wallet

- Ordinary image editing and JSON mask editing retain separate examples. Mask examples correctly encode `image_urls` as an array.
- Skills, prompts and categories preserve the Web server's order; selecting a category no longer unexpectedly rearranges navigation.
- Issued invoices show email progress. Acceptance by the email service is not claimed as delivery; failed or unconfirmed sends direct users to staff review without reapplying or paying again.

- History refreshes once when opened, without a manual refresh button. Scrolling to the bottom loads the next page; failures retain existing records and retry the failed page.
- Added read-only invoice history with titles, statuses, invoice totals, fees, invoice numbers and issuance times. Applications, payments and downloads remain on Web.

- Balance history labels code credits as “Redemption code” and keeps them in the same paginated ledger as online top-ups. Older code credits remain loadable with recorded credit, status and a copyable reference, separate from membership activations.

- Membership terms preserve hours, months, years and custom seconds; calendar orders with no day count no longer fail to load. Historical entitlements remain, without displaying or copying retired activation codes. Balance redemption-code credits are unaffected.
- Partial wallet refreshes retain previously loaded reward and adjustment notifications. Unknown notification counts display a dash instead of claiming everything is read; account changes clear previous-account views.
- Wallet history distinguishes recorded payment currency from credited USD; unpaid orders no longer imply a completed credit. Alipay and WeChat Pay use matching bundled brand marks. Membership history includes online purchases alongside historical activations with independent pagination and refresh. Records follow Web's timestamp/status header, title/payment row, right-aligned credit and membership validity footer, without duplicate labels or empty completion times. Usage history explains the 100-page limit and links back to filters.

- Media examples accept catalog-declared data URL inputs. Details show declared output sizes, task states and read-only polling examples, with recovery and duplicate-submission safeguards. Missing capabilities or sizes are not inferred; the page never generates or polls automatically.
- Media pricing hides unmapped fallback specifications and bases additional-fee notes only on visible prices. Referral statistics use “Total eligible top-ups”, and max reasoning effort has a dedicated style in usage records.
- Model details have separate API examples, overview and price tabs. Multiple-tier models open pricing by default; group, currency and Token-unit selections remain when switching tabs. Price conditions, specifications and additional fees follow Web.
- Usage details occupy 50% of the desktop window and show historical quantities, official unit prices, subtotals and the recorded total in the footer. Pending holds remain separate from consumption, with refund signs preserved. Billing timestamps prefer their recorded historical timezone; current prices never recalculate old charges.
- Available credit, subscriptions, membership and enterprise information support one background continuation. Same-account stale values remain visibly stale and cannot establish redemption or offer eligibility. Navigation and billing offers stay hidden while enterprise credit is unresolved or stale, even if the previous snapshot showed zero credit or no membership.
- Codes use the wallet redemption endpoint; membership history remains readable. Purchase and official-site links open the Web wallet; Switch does not create online payment orders. Records retain source, payment method, occurrence time, cancelled/expired/unknown states and balance activity.
- Support uses “New users: join group for $5” and navigation uses “New users get $5” only after available credit is known to be zero. These labels do not grant credit automatically. Task history allows at most 200 items per page, with category counts across the project.

## Assistant and creation boundaries

- Each shot and the final episode or canvas output accepts ±1 second, including the boundary, without blocking or regenerating within tolerance; tolerances do not accumulate per shot. Aspect, content and quality checks remain.
- Automatic approval covers declared assistant operations, not manual generation controls; file export still requires confirmation. Permissions remain revocable, and unknown costs or uncertain submissions pause the relevant action.
- Stopping the assistant does not cancel or refund submitted cloud tasks; results continue under the original task identity. A saved current output is required: a model statement or older candidate is not completion evidence. History stays readable while work runs, including header information dialogs.
