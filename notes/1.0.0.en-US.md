# Pure Tokens Switch 1.0.0

One-click configuration now changes only explicitly Switch-owned fields while preserving personal client settings, nested options and custom labels. This fixes false conflicts caused by additional settings in Claude Desktop and other clients.

## Configuration compatibility

- Claude Desktop cost-estimation settings and other extra fields no longer cause false provider-ownership conflicts. Inspection, reconfiguration, direct-to-mapped transitions and restore preserve their values and types.
- File adapters in the compatibility matrix merge owned fields without rejecting unfamiliar names or types of unrelated properties. Preserving data does not certify that a third-party host accepts arbitrary setting types.
- Correct Claude Code inspection with customized descriptions, MiniMax nested capability and default-preference preservation, and byte-idempotent DSH reconfiguration. Factory custom display text must retain its ownership prefix; personal entries without that prefix are not adopted.

## Model changes and restore

- Preserve customized old records during reconfiguration and model changes without transferring their settings to a different model.
- Restore disconnects managed credentials and defaults according to each client contract. Retired independent connections remove stale keys; shared connections keep required endpoint and key updates. Customized Gemini aliases and definitions are retained together and deactivated.
- Actual ownership, authentication, protocol, path and concurrent-write conflicts remain protected. Original-byte checks, backups and transactional rollback are unchanged.

## Usage boundaries

- Preference-conflict guidance asks users to check model filters or adjust their selection, not remove unrelated settings. OpenCode and Oh My Pi filters that hide selected models still need adjustment.
- OpenMausBot vendor restore remains unavailable; Claude Desktop private Skills receipt validation is not relaxed. VS Code configuration remains file-only and does not start or restart the editor.
- Existing 0.8.1 model catalog, usage, redemption-code top-up, membership and invoice history remain available. Configuration preservation adds no HTTP or IPC fields; network selection adds local settings and diagnostic networkMode fields, with no new HTTP routes, error codes, database migrations or Web changes.

## Application service connection

- Select System proxy or Direct before sign-in and in Settings. System proxy remains the default. Direct applies only to Switch Product API requests; it does not alter system proxy or certificate settings, or control the updater, tool downloads, third-party clients or Claude model mapping.
- The preference uses local settings schema 5; older settings default to system and failed persistence retains the previous mode. Switching refreshes anonymous checks without signing in or replaying in-flight actions. Diagnostics include the selected mode, never proxy addresses.

## Retained client and account capabilities

- Claude-3p supports the default bearer authentication mode. Windows Claude Desktop uses Local AppData rather than the former Roaming location. Reapply configuration after upgrading from the old location; the original directory is preserved and runtime activation requires host verification.
- The model catalog retains separate examples, overview and pricing tabs based on declared capabilities. Usage history keeps historical prices and settled amounts rather than recalculating them with current prices.
- Wallet history refreshes once when opened and loads more on scrolling, including redemption-code top-ups, membership purchases and read-only invoice records. Payments, invoice applications and downloads remain on Web; email-service acceptance does not establish delivery.
- Support retains “New users: join group for $5” and navigation retains “New users get $5” only when credit and enterprise state establish eligibility. These labels do not grant credit automatically. Task history supports at most 200 items per page with category counts across the project.

## Assistant and creation boundaries

- Each shot and the final episode or canvas output accepts ±1 second, including the boundary, without blocking or regenerating within tolerance; tolerances do not accumulate per shot. Aspect, content and quality checks remain.
- Automatic approval covers declared assistant operations, not manual generation controls; file export still requires confirmation. Permissions remain revocable, and unknown costs or uncertain submissions pause the relevant action.
- Stopping the assistant does not cancel or refund submitted cloud tasks; results continue under the original task identity. A saved current output is required: a model statement or older candidate is not completion evidence. History stays readable while work runs, including header information dialogs.

## Installation and verification

The Windows x64 and macOS Apple Silicon installers passed user acceptance for this release. The maintainer confirmed stable core account, configuration apply and restore, direct client requests, usage, redemption-code, status-bar and in-app update flows. All three platforms share the same frozen source commit, with verified updater signatures, provenance, licenses and artifact integrity.

macOS Intel passed same-source cross-compilation and package-content verification; native Intel device smoke remains deferred. Community installers are not Apple Developer ID notarized or Windows Authenticode signed. Tauri Updater uses independent signature verification. General acceptance does not establish coverage of every third-party host version or all paid requests.
